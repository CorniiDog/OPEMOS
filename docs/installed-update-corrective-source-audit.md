# Installed updater corrective source audit, 2026-10-15

Status: INCOMPLETE SOURCE DRAFT; production update disabled. This is a bundled
owning-component audit, not acceptance, a new infrastructure task, or a request
for broader authority. The prior 12e6bef checkpoint and all failures remain.

The reproduced product blocker is the prior complete-writer refusal: installed
module/initramfs/configuration updates cannot run because a retry journal and
trap rollback cannot recover abrupt power loss. The owning component is Core's
installed NVIDIA producer, artifact transaction and guardian. This directly
blocks installed automatic update/maintenance; the three-kernel compiler route
and EXE builds are independent and are not stopped by this draft.

## Authored current joins

* `bootstrap/install.sh` routes original installed roots to the owning
  controller; only a kernel-verified overlay staging context admits the old
  opaque writer. The controller deliberately refuses production updates while
  the remaining joins below are incomplete.
* `installed_driver_candidate.py` drafts private overlay production, immutable
  input snapshots, complete upper-effect enumeration, prior receipt/module/boot
  checks, boot-last artifact planning and exact installed-policy binding. This
  namespace draft has NOT been exercised and is NOT approved confinement.
* `installed_update_transaction.py` separates prepare/commit so old/new bytes,
  modes and intent are durable before root policy changes. Explicit parent
  directory flushes supplement atomic_output's file-only flush. Original
  absence is recorded and only exact owned new bytes may be removed during
  rollback. Unknown bytes/modes hold recovery. Evidence is retained.
* Startup/health CLI dispatch uses the owning policy/controller, existing
  recovery/lifecycle locks and manager lock. Actual boot IDs distinguish
  activation, first new boot and repeated unacknowledged reboot. Health compares
  selected disk artifacts and actual loaded source identities. Guardian source
  snapshots include the new imports; guard invokes startup before status.
* Actual initial module verification reuses the decompressed payload verifier.
  Its moduleName/actualPayloadSha256 schema must not be confused with the
  compressed cached-repair receipt's name/sha256 schema.

## Remaining source defects, bundled before runtime

1. **Production candidate confinement remains unverified.** Target
   `lsinitcpio`, execution-input snapshots and initramfs verification now run
   inside the same private PID/network/mount namespace as the old writer.
   Collection reads retained evidence without executing target code. Capability
   allowlists drop SYS_CHROOT after chroot, MKNOD, DAC_READ_SEARCH and other
   kernel/device capabilities; proc and sys are read-only. Pre/post execution
   snapshots agree. Those are source changes only. Actual namespace, UID,
   sudo/capability and complete descendant closure properties require real VM
   verification. Deeper mount coverage is still not proven or refused by this
   draft; five top-level overlays cannot be assumed to cover every mount.
2. **Fallback writer join.** Recovery enable/disable still require a staged
   context without a complete owning dispatch. The closed file plan rejects
   default.target symlinks; enable-fallback must use offline systemd operations,
   not affect the live display manager, and must validate its intentional
   non-NVIDIA initramfs instead of the normal four-early-NVIDIA verifier.
   A fallback cannot be acknowledged by requiring a loaded NVIDIA DRM module.
3. **Cached/online receipt and retry join.** Cached receipt construction exists
   in candidate collection, but recoveryctl still has a live post-install
   receipt commit and online_install retains/commits after installation.
   Snapshot authenticated canonical products before production, commit their
   receipt within the candidate, and keep the retry journal pending until real
   boot health. A file-only status must not terminate an unacknowledged update.
4. **Mounted offline image writer.** install_to_root remains refused. Its
   package/userspace/hooks/EFI/payload receipt effects exceed the installed
   driver-only allowlist and its existing root/execution validation must remain.
   Complete the owning unpublished-image transaction under the existing image
   generation/export contract; do not enable it by deleting require-plan or
   using a caller-provided completeWriterSet Boolean. This is a different
   producer profile from an installed-root driver-only update.
5. **Guardian/app persistence.** Current guardian refresh still copies code and
   policy in place. Source distribution and systemd entrypoint changes need a
   durable generation join; otherwise abrupt loss can strand the consumer that
   is needed to restore the driver. Source/policy changes while a driver is
   pending must be serialized and preserve the exact compatible prior
   authority. No new authority, slot contract or opaque app copy is allowed.
6. **Health scheduling and consumers.** The explicit installed-health command
   is authored but a correctly ordered persistent service/timer and failure
   consumer have not been connected. Boot health must not run before startup
   attempt registration or be synthesized by ordinary status. Actual sysfs
   srcversion availability is a VM/hardware property to measure, not mock.
7. **Verification completeness.** New ordinary raw-plan CLI/UID/schema tests
   are authored, not run. They do not exercise actual namespace production or
   guardian/app persistence. The full production transaction and real
   abrupt-VM-off/reboot/repeated recovery, including filesystem/clock/UID/budget
   assumptions, still require source completion, independent review and fresh
   separately admitted OMEN verification. No frozen real input/output manifest
   can truthfully be labeled completed before that admitted run.

8. **Initial LKG and controlled self-heal.** A valid initial payload receipt
   and on-disk image hashes are not evidence of an actual successful prior boot.
   An acknowledged retained generation supplies stronger evidence; initial
   adoption still needs the existing compatible usable-boot proof or owning
   base-OS fallback contract. A changed/foreign current artifact currently
   holds rather than entering automatic repair. Preserve that evidence and
   finish the explicitly authorized exact-owned corruption repair policy before
   describing this as complete self-heal. Do not silently treat corrupt current
   bytes as a known-good rollback or broaden deletion authority.
